# 手工计划与甘特图（M2）设计及验收

## 范围

在 Ply 中新增独立的「计划」视图，维护计划项目 → 需求 → 子任务三层结构。计划项目与现有 Git 仓库项目分开存储；计划数据保存在本地 App DB 的 KV 命名空间中，不创建仓库/Agent 任务，也不调用规划器或启动 Agent。M1 仍为暂缓验收。

## 设计

- 复用现有 Workbench view、侧栏入口、Wire domain client 和 AppDb。单份版本化 JSON 文档保存项目、需求、子任务、日期、顺序和依赖；M2 不新增 SQL 表或迁移。
- Node 服务负责所有读改写：输入校验、稳定排序、日期范围验证，以及将新增依赖与现有依赖图合并后做环检测。拒绝非法变更时不写库。
- 视图支持新增项目/需求/子任务、展开/收起需求、调整子任务日期与上下顺序、添加/移除依赖。日期轴根据任务日期展示条形跨度；依赖及日期都以清晰表单控件编辑。
- UI 仅提交显式用户操作；打开视图、加载计划和添加计划项均不触发 Agent、自动排期或执行。

## 验收映射

| 需求 | 验收动作 | 通过证据 |
| --- | --- | --- |
| 多项目与层级 | 创建两个项目；每个项目建立一个需求和两个子任务；展开/收起需求。 | UI 显示两个独立项目及各自的需求和子任务；层级操作只影响对应需求。 |
| 日期与顺序 | 修改任务起止日期；用上移/下移调整顺序。 | UI 日期输入、甘特条和列表顺序一致；结束早于开始被拒绝。 |
| 依赖与环检测 | 建立 A→B，再尝试 B→A；尝试自依赖。 | 合法边显示；成环/自环被拒绝且原图不变。 |
| 持久化 | 写入上述两项目数据，关闭并重新打开 app/重新加载计划。 | 项目、需求、任务、日期、顺序和依赖完整保留。 |
| 无自动执行副作用 | 新建和编辑计划项时观察行为及 Wire 调用。 | 只调用计划读写接口，不启动规划 Agent、Codex 或任务执行。 |

先用纯逻辑与 SQLite 重开测试验证模型、校验、事务和持久化，再用浏览器组件测试验证实际交互。若 Cloud Electron 无法运行，明确将桌面关闭/重开验收列为未验证，不用测试替代声称通过。
